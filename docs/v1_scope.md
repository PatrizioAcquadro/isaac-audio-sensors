# V1 Public Scope

This is the public source of truth for the `isaac-audio-sensors` v1 release
scope. Other docs may explain usage or validation details, but this page owns
what v1 promises and what it explicitly does not promise.

The v1 release is a reusable Isaac audio sensor package. It is not a release
gate for SquadBot, Alex, ROS 2, or any downstream research system.

## V1 Promises

| Category | V1 scope | Release meaning |
| --- | --- | --- |
| Stable public contract | Stable `AudioSensorFrame` v1 public contract | The `ias.audio_sensor_frame.v1` JSON shape, stable fields, units, provenance values, coordinate convention, ambiguity fields, schema export, and trace round-trip behavior are compatibility commitments for compatible v1 releases starting with `1.0.0rc1`. |
| Stable backends | Stable L0 `geometry_only` backend | Deterministic bearing, distance, sector, `max_events`, and frame-contract behavior are stable v1 runtime behavior. |
| Stable backends | Stable L1 `tdoa_synthetic` backend | Deterministic direct-path synthetic delay/RMS diagnostics, stress controls, and explicit two-mic ambiguity metadata are stable v1 runtime behavior. |
| Supported optional backend | Supported optional L2 `room_acoustics` backend | The backend is dependency-gated behind the `room` extra, skips or raises clear optional-dependency errors when absent, and records stable L2 diagnostics when present. |
| Supported integrations | Supported Isaac Sim live sensor path | The lazy Isaac Sim sensor lifecycle, stage snapshot capture, semantic discovery, live transform reads, and JSON/JSONL trace output are supported when a user-managed Isaac Sim runtime is available. |
| Supported integrations | Supported Isaac Lab sensor path | The lazy Isaac Lab sensor layer, real `SensorBase` recovery after runtime initialization, fixed-shape observation buffers, stage binding, entity binding, and GPU-required validation path are supported when a user-managed Isaac Lab runtime is available. |
| Supported integrations | Omniverse extension as the reference UX | The bundled Kit extension is the reference authoring and inspection UX for arrays, sources, live sensor control, overlays, JSON/JSONL export, config import/export, and optional extension recording. |
| Stable export | Stable JSON/JSONL export | `frame_to_trace_dict`, `frame_from_trace_dict`, JSON schema export, JSON frame files, and JSONL frame streams are the package-native trace format for v1. |
| Optional extension capability | Replicator as an optional extension capability | Replicator support is only an Omniverse extension capability. It is imported lazily inside Isaac Sim/Kit, may be unavailable in some Kit runtimes, and never becomes a requirement for core import, `AudioSensorFrame`, JSON/JSONL export, the Isaac Sim base sensor, or the Isaac Lab sensor. |

## Explicit Non-Promises

V1 does not promise these items. They must not be treated as package release
gates:

- SquadBot as a v1 release gate.
- Sim-real calibration.
- Real hardware benchmarks.
- Complete L3/L4 acoustic fidelity.
- Realistic occlusions or material acoustics.
- Mandatory ROS 2 or downstream adapters.
- Alex or SquadBot validation before releasing the sensor package.

Useful downstream references may remain in docs when they are clearly optional,
historical, or adapter-oriented. They must not redefine the v1 release scope.

## Release Gate Policy

Core v1 release candidates must verify the stable frame contract, schema
parity, JSON and JSONL trace round trips, L0/L1 behavior, optional L2 behavior,
package import safety, lint, build, import smoke, and distribution audit.

Isaac Sim and Isaac Lab live checks are release gates for the supported live
sensor paths when an installed runtime is available. If a live runtime is
blocked by sandboxing, EULA, GPU visibility, display, or runtime availability,
the release record must include the exact command, exact error, and any evidence
file generated by the failed attempt.

The Omniverse extension UX smoke is the release gate for the reference UX when
Kit is available. Replicator validation is an optional extension-capability
gate: a missing Replicator runtime must not block the core v1 package unless the
release specifically claims Replicator is enabled for that environment.
